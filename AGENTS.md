## Контекст и порядок работы

- Сначала интерпретировать последний запрос пользователя. Для новой задачи читать только известные инструкции/пути; если пути неизвестны — [INDEX](docs/context/INDEX.md) и 1–2 домена. Не перечитывать неизменённые документы внутри сессии.
- До существенной работы создать отдельный TASK через [Context OS](docs/context/README.md): дословный доступный запрос (или явно отмеченная реконструкция), scope, запреты, измеримые критерии, зависимости/риски, файлы/проверки и следующий шаг. Секреты и данные покупателей в записи не включать.
- Требования не стирать; новые поручения добавлять датированными поправками. Новые критерии — в amendment.acceptance. Несколько задач имеют разные файлы; другая задача не уничтожает прежнюю.
- При продолжении выбрать задачу по намерению пользователя: task + последняя валидная checkpoint-цепочка + сверка Git/status/хешей текущих файлов. Не выбирать по самому новому файлу. Команда: node scripts/context-os.mjs resume TASK-ID.
- При несовпадении указателей перечислить валидные checkpoints и восстановить после сверки снимка; внезапный сбой мог оставить незаписанную работу. Не повторять внешние записи и неидемпотентные команды автоматически.
- Выполнять небольшими проверяемыми шагами; учитывать связанные контракты/вызовы/тесты, без постороннего рефакторинга. Сохранять checkpoint после важного проверенного результата, перед переключением/риском и нормальным выходом.
- Checkpoint: уникальный append-only файл → readback → task/state/pointer → registry последним → проверка ссылок. Реестр — только указатели, не второй статус. Task/registry обновляются с наблюдённым hash; shared docs перед записью перечитать/сравнить. При конфликте не затирать, объединять только явно независимые изменения.
- DONE только через VERIFYING после подтверждения всех исходных/добавленных критериев или явной уступки владельца. FAIL/NOT RUN/DESIGN REVIEW ONLY не успех. Не скрывать незавершённое; хранить nextStep/blockers. Повторное открытие DONE — явная запись.
- Код/конфигурация важнее устаревшей документации. Метки VERIFIED / USER_SPECIFIED / PROPOSED / UNKNOWN / OBSOLETE; существенные факты имеют источник и дату. Обновлять только затронутые знания. Не заявлять гарантированную память/блокировку или измеренную экономию токенов без доказательства.
- [PROJECT_CONTEXT](PROJECT_CONTEXT.md) — стабильная карта, [PROJECT_STATE](docs/context/PROJECT_STATE.md) — возможности и ограничения, [реестр](docs/context/TASK_REGISTRY.md) — задачи. Канонический контекст в docs/context, потому что .codex игнорируется; .gitignore/hooks не менять по умолчанию.
