GRACE COSMETICS — ЗАПУСК И ПЕРЕДАЧА ПРОЕКТА НОВОМУ ЧЕЛОВЕКУ
Состояние на 13 октября 2026 года
Репозиторий: https://github.com/gracecosmeticsru/grace

Этот файл можно открыть обычным Блокнотом. Он рассчитан на человека,
который не участвовал в предыдущей переписке.

1. ЧТО ВЫ СКАЧАЛИ

Это существующий магазин Grace Cosmetics: исходники страниц и сервера,
каталог, фотографии, исходные материалы, тесты и история разработки.
Стек: TypeScript, React, Vinext/Vite и Cloudflare Workers; для заказов — D1.

Есть 4 526 карточек, 6 089 вариантов и 350 брендов. Каталог хранится
в data/, фотографии — в public/, исходные таблицы и материалы — в materials/.
Цены в JSON не являются подтверждением сегодняшней цены или наличия.

Скачивание исходников позволяет запустить витрину и продолжить разработку.
Оно не передаёт доступ к действующему хостингу, Telegram-боту, СДЭК,
рабочей базе заявок или кабинету владельца. Часть задуманных функций ещё
не реализована: одними ключами доступа их включить нельзя.

Функциональное состояние после чистой установки:
- Страницы, каталог, фильтры, поиск, бренды, фото, статьи — доступны.
- Варианты товаров, корзина, избранное, история просмотра — работают
  в браузере текущего посетителя. Между устройствами они не синхронизируются.
- Страница оформления есть; приём настоящих заявок по умолчанию закрыт.
- Серверное сохранение заявок и очередь Telegram реализованы; им нужны
  отдельная база, настройки хоста, флаги и секреты, см. разделы 5–7.
- Выбор города и ПВЗ СДЭК реализован, но требует действующей авторизации.
- 1С, подтверждённые текущие остатки, кабинет покупателя с кодами входа,
  межустройственная история и уведомления о поступлении ещё не завершены.
- Онлайн-оплата не подключена.

2. ПЕРВЫЙ ЗАПУСК НА ДРУГОМ КОМПЬЮТЕРЕ

Нужны:
1) Node.js с npm. Для воспроизведения этой проверки использованы
   Node.js 22.23.3 и npm 10.9.9 на Windows x64. Минимум проекта — 22.13.0.
   Официальная загрузка: https://nodejs.org/en/download
2) Интернет для первой установки зависимостей.
3) Git, если скачиваете через git clone. При скачивании ZIP он не нужен
   для обычного локального запуска, но понадобится для истории и обновлений.

После установки Node.js откройте новое окно терминала:

  node --version
  npm --version

Скачать через Git:

  git clone https://github.com/gracecosmeticsru/grace.git
  cd grace

Либо нажмите Code -> Download ZIP на GitHub, распакуйте архив и откройте
терминал именно в папке с package.json. Название папки может быть другим.
Путь D:\grace из старых отчётов относится к компьютеру владельца;
на вашем компьютере этот путь создавать не требуется.

В папке проекта выполните по очереди:

  npm run install:ci
  npm run dev -- --hostname 127.0.0.1

Дождитесь строки Local: http://127.0.0.1:5173/ и откройте этот адрес.
Первый запуск может занять больше времени из-за подготовки зависимостей.
Не закрывайте терминал, пока пользуетесь сайтом. Остановка — Ctrl+C.

Если Windows PowerShell блокирует npm.ps1, используйте npm.cmd вместо npm
или обычную Командную строку. Ослаблять политику безопасности PowerShell
для этого не требуется.

Если порт 5173 занят:

  npm run dev -- --hostname 127.0.0.1 --port 5183

Смотрите адрес, напечатанный сервером. В проверке отдельной копии
использовался http://127.0.0.1:5183/, чтобы сохранить основной сайт владельца.

После первой установки на Windows можно запускать start-local.cmd.
Для проверки обычной витрины аккаунт Codex, API-ключи и файл .dev.vars
не требуются. Не копируйте чужие node_modules: они устанавливаются заново
для вашей ОС через npm run install:ci и сохранённый package-lock.json.

3. СБОРКА И ПРОВЕРКИ

Из корня проекта:

  node node_modules/typescript/bin/tsc --noEmit --incremental false
  npm run test:logic
  npm run build

test:logic проверяет только часть логики. Для всех 104 локальных тестов
из этой проверки в PowerShell выполните:

  $graceTests = Get-ChildItem tests/*.test.mjs | Where-Object Name -ne 'catalog-api.test.mjs' | ForEach-Object FullName
  node --experimental-strip-types --test --test-concurrency=1 $graceTests

Для API-проверок запустите dev-сервер на 5173 в отдельном терминале:

  npm run test:api

Если сервер на 5183, в PowerShell перед API-тестом задайте:

  $env:GRACE_BASE_URL = 'http://127.0.0.1:5183'
  npm run test:api

Просмотр production-сборки после успешного npm run build:

  npm run start -- --port 5184

Адрес: http://127.0.0.1:5184/. Это локальный просмотр Worker, а не публикация.
Все результаты именно чистой проверки перечислены в
docs/CLEAN-CLONE-CHECK.md. Успешные тесты с имитацией внешних сервисов
не подтверждают доступ к реальному Telegram, СДЭК или 1С.

4. ЧТО НЕ ХРАНИТСЯ НА GITHUB

- node_modules, dist, .next, .vinext: зависимости, сборки и кеши; создаются
  установкой, запуском и сборкой.
- .env*, .dev.vars*: секретные настройки. Владелец передаёт необходимые
  доступы отдельно безопасным способом либо выдаёт новые.
- .wrangler: локальные базы и состояние Workers. В репозитории есть
  структура и миграции, но нет самих заявок покупателей.
- .sites-runtime, .codex, .unlazy и artifacts: локальные настройки,
  результаты проверок, журналы и служебные файлы. Для витрины они не нужны.
- localStorage: корзина, избранное и история конкретного браузера.

Нужны отдельные резервные копии рабочей базы и безопасное хранение секретов.
GitHub не заменяет их. Не добавляйте реальные контакты покупателей, токены,
пароли или выгрузки заявок в публичный репозиторий.

5. ХОСТИНГ И БАЗА ЗАЯВОК

У проекта есть серверные маршруты и Workers-зависимости. Просто разместить
эти файлы на GitHub Pages или открыть HTML с диска недостаточно для заказов.

Вариант существующего магазина: владелец должен предоставить доступ
к его проекту Sites и соответствующей D1. Скачать GitHub недостаточно.
Публикация через Sites выполняется в правильный проект с его runtime
настройками и миграциями. ID в .openai/hosting.json относится к существующему
проекту и не выдаёт права на него.

Для собственного развёртывания Cloudflare требуется отдельная настройка:
Worker/домен/HTTPS, настоящая D1, binding с именем DB, секреты и конфигурация
публикации. В vite.config.ts используется заглушка database_id для локальной
эмуляции; это не идентификатор рабочей базы. dist/server/wrangler.json
генерируется при сборке, поэтому ручные правки в нём не являются постоянной
конфигурацией. Нужен проверенный путь развёртывания с настоящими binding/ID.

Основной файл .openai/hosting.json сейчас содержит d1: null, r2: null.
Это позволяет запустить витрину без доступа к облаку. Для обычного локального
подключения D1 конфигурация должна содержать d1: "DB"; создание рабочей
облачной D1 и назначение её настоящего ID выполняются отдельно.

Схема для новой базы действующего варианта заказов находится в drizzle/.
Порядок определяется drizzle/meta/_journal.json:
  0000_friend_orders.sql
  0001_friend_order_notification.sql

Применять их к новой или проверенной целевой базе в указанном порядке.
Не накладывать вслепую одновременно drizzle/ и db/migrations/: последняя
папка содержит миграции прежних локальных тестовых сценариев.
Не запускать повторно уже применённые SQL без сверки схемы и миграций.
Перед изменением существующей базы нужна её резервная копия.

Для локальной D1 после настройки binding DB и повторной сборки команды
из README выглядят так (это локальная база, не облачная):

  node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_friend_orders.sql
  node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_friend_order_notification.sql

Эти команды сами по себе не открывают приём заявок. Флаги и точный хост
тоже должны соответствовать выбранному режиму. GRACE_ORDER_TEST_MODE —
отдельный локальный тестовый режим; его не включают на рабочем хостинге.

6. ЧТО НАСТРОИТЬ ДЛЯ ПРИЁМА ЗАЯВОК

Код проверяет одновременно базу DB, точное имя хоста, флаг включения
и параметры Telegram. Основные имена настроек:

  DB                         binding базы D1, не строка с паролем
  GRACE_ORDERS_ENABLED        1 только после проверки всех зависимостей
  GRACE_ORDER_HOST            точный host, без https:// и без пути
  GRACE_TELEGRAM_BOT_TOKEN    серверный секрет токена бота
  GRACE_TELEGRAM_CHAT_ID      проверенный числовой ID группы
  GRACE_CDEK_PICKUP_ENABLED   0 до успешной проверки настоящего СДЭК
  CDEK_ACCOUNT               серверный идентификатор доступа СДЭК
  CDEK_SECURE                серверный секрет СДЭК

Для localhost с нестандартным портом host включает порт. На хостинге
параметры задаются через runtime Variables/Secrets выбранной платформы.
Секреты не должны попадать в клиентские переменные или сборку браузера.
Нельзя включить все функции, просто вписав эти строки в исходный код.

Пока проверяются настройки, оставляйте GRACE_ORDERS_ENABLED=0.
При неподключённой базе или выключенном режиме ответы 503 от маршрутов
/api/orders и /api/orders/session являются ожидаемой блокировкой приёма.

Для приёмки после настройки: согласовать один вымышленный заказ,
проверить сохранение состава и суммы, переживание перезапуска, защиту
от дубля, запись очереди и ровно одно уведомление нужной группе.
Не повторяйте исторические тестовые заказы из старых отчётов.

7. TELEGRAM: ВАЖНОЕ ОГРАНИЧЕНИЕ ТЕКУЩЕЙ ВЕРСИИ

Нужны собственный либо разрешённый владельцем бот, группа и права бота
отправлять сообщения. Токен и числовой chat_id передаются безопасно.

В lib/order-runtime.ts и scripts/telegram-local.mjs сейчас явно проверяется
название группы «Тест группа». Для другой рабочей группы разработчик должен
согласованно изменить эту проверку и связанные тесты, затем подтвердить
именно новый числовой ID и права. Простая замена токена не меняет адресата.

scripts/configure-telegram.ps1 и scripts/telegram-local.mjs обслуживают
отдельный локальный сценарий с .dev.vars.telegram и .wrangler/order-test.
Они не настраивают автоматически runtime Secrets опубликованного сайта.
Режим --live действительно обращается к Telegram; не запускайте отправку
без разрешённого адресата и согласованного теста.

Уведомления хранятся в очереди. Сейчас обработка запускается при успешном
трафике оформления. Независимое расписание повторов ещё не подключено:
после долгого сбоя Telegram очередь может ждать нового посетителя.
Для надёжной постоянной работы нужен отдельный серверный запуск обработчика
по расписанию, с сохранением блокировок и защиты от повторов.
Для статуса delivery_unknown сначала сверяйте сообщения в группе;
слепой повтор может создать дубль.

8. СДЭК И ОСТАЛЬНАЯ ДОСТАВКА

Нужны действующие CDEK_ACCOUNT и CDEK_SECURE для правильного API-окружения.
Последняя проверка прежней пары 12 октября вернула OAuth 401. Значения
в GitHub отсутствуют. Более ранняя запись о сетевом таймауте в
docs/CDEK-INTEGRATION.md является исторической; новый статус указан в
docs/FRIEND-ORDERS.md и начале AGENTS.md.

После получения доступа сначала проверить авторизацию, города и ПВЗ,
затем включать GRACE_CDEK_PICKUP_ENABLED=1. Локальные настройки — в
игнорируемом .dev.vars; на хостинге — серверные Secrets. Проверка должна
охватывать как список ПВЗ, так и повторную серверную проверку при заказе:
они читают настройки через разные runtime-интерфейсы.

Существующий код выбирает город/ПВЗ. Он не создаёт отправление в СДЭК,
не печатает накладные и не рассчитывает окончательный тариф.
Курьер и Почта сейчас собирают адрес; создание отправлений и стоимость
согласуются менеджером. Для автоматизации перевозчиков нужна разработка.

  тестовое ограничение из lib/demo-inventory.ts. Сейчас там 1 шт. на вариант;

- Исходный Grace_1C_FINAL_IMPORT_5051.xlsx отсутствует; результат его

  и не запускайте импортёр с другой таблицей поверх действующего каталога.

Кабинет, доступ по телефону и история на разных устройствах:
- Выбрать и подключить сервис одноразовых кодов.
- Реализовать подтверждение телефона, ограничения попыток, защищённые
  сессии, выход и серверные проверки доступа к каждому заказу.
- Безопасно связать гостевые заказы с подтверждённым профилем, добавить
  историю, адреса и синхронизацию. Одного введённого номера недостаточно
  для раскрытия старых заказов.
- app/chatgpt-auth.ts и местный тестовый вход — инфраструктура платформы,
  не готовый кабинет покупателя Grace и не система SMS/WhatsApp-кодов.

Уведомления о поступлении и WhatsApp:
- Текущая ссылка WhatsApp открывает контакт магазина вручную.
- Автоматические сообщения требуют выбранного официального провайдера,
  доступов, необходимых шаблонов/разрешений и серверной очереди.
- Для поступлений нужны реальные изменения наличия из 1С, подписка на
  точный вариант, согласие/отписка и защита от повторных уведомлений.
- Канал уведомлений о новых заявках менеджеру сейчас Telegram. Старые
  документы с планом отправки менеджеру через WhatsApp не меняют это решение.

Оплата:
- Сейчас онлайн-оплаты нет; заказ является заявкой для подтверждения.
- Для оплаты нужно выбрать эквайринг и реализовать серверное создание
  платежа, проверку уведомлений, идемпотентность, статусы и возвраты.
  Это отдельная работа, не недостающий файл из скачанного проекта.

Наполнение:
- Не все товары получили фотографии, описания, составы и инструкции.
- Продолжать по materials/catalog-7b/manifest.json, не перезапуская очередь.
- Новые фото брать из реальных источников; не найденные отмечать как пропуск.
- Сохранять исходные ID товаров/вариантов и различать размеры/оттенки.

12. КАК СОХРАНЯТЬ ДАЛЬНЕЙШИЕ ИЗМЕНЕНИЯ

После выполненной задачи: проверить результат, обновить документацию,
просмотреть git diff, создать коммит и отправить его на GitHub.
Для записи в gracecosmeticsru/grace нужны права владельца/соавтора;
публичное скачивание не даёт права отправлять изменения. Другой человек
может работать в своём fork и предложить pull request.

Перед началом работы проверять актуальность своей ветки. Не использовать
force-push и не стирать чужие изменения. Публикация кода на GitHub
не обновляет автоматически работающий сайт.

Историческое правило «работать только D:\grace» защищает основной checkout
владельца. Для отдельно разрешённой проверки, клона на другом компьютере
или собственного fork рабочей папкой является выбранная копия.
