# Диагностический захват штатного обмена 1С

15.10.2026. Подготовка для [9А](1C-INTEGRATION.md), [задача](context/tasks/TASK-20261015-001.md). Это локальный инструмент получения фактического образца. Он не подключает данные к витрине и не завершает 9А или 9В.

## Как устроена проверка

1С на этом компьютере отправляет каталог в отдельный приёмник `http://127.0.0.1:5179/exchange`. Интернет для этого соединения не нужен. Адрес работает только на компьютере приёмника: если 1С запускается на другом устройстве, эта схема не подходит. Основной сайт на5173 и опубликованные сайты не используются.

Приёмник поддерживает только каталог. После авторизации принимает исходные байты файлов/частей и сохраняет их в исключённой из Git папке. Он не разбирает XML, не распаковывает ZIP, не меняет товары, цены, остатки или заявки и не передаёт заказы в1С. Принятые файлы нельзя скачать через HTTP.

По [официальному протоколу1С](https://v8.1c.ru/tekhnologii/obmen-dannymi-i-integratsiya/standarty-i-formaty/protokol-obmena-s-saytom/) ответ `success` на `file` подтверждает запись файла/части, а на `import` — успешное окончание обработки файла. Поэтому диагностический приёмник на **каждый import возвращает**:

```text
failure
Diagnostic capture only; import disabled
```

Это ожидаемая остановка проверки, не признак готового обмена. `progress` и фиктивный `success` при импорте не используются. Отсутствие подтверждения импорта не доказывает, что конкретная1С не изменит служебные записи/регистрации обмена. Настройка узла и ручной запуск согласуются как отдельное конкретное действие; учётных операций ради теста не выполнять.

## Запуск на компьютере проекта

Из `D:/grace`:

```powershell
node scripts/one-c-diagnostic.mjs
```

По умолчанию порт5179; если он занят, не останавливать чужой процесс. Временные данные подключения находятся в `.unlazy/1c-diagnostic/connection.json`. Логин/пароль от магазина, старого сайта, СДЭК или администратора1С здесь не используются. Секреты не копировать в отчёты, задачи или Git. Учётные данные и исходные выгрузки остаются только локально; `.unlazy/` уже исключена из репозитория.

## Проект нового штатного узла — не применён

Использовать «Сервис → Обмен с сайтом → Настройки обмена с сайтом». По словам владельца штатный список был пуст; старый профиль дополнительного модуля «Grace» не трогать. Имя нового диагностического узла: **Grace — диагностика**.

| Поле/режим | Значение для согласованного ручного прохода |
|---|---|
| Адрес сайта | `http://127.0.0.1:5179/exchange` |
| Пользователь/пароль | Временные значения из локального файла подключения |
| Выгрузка товаров | Включить |
| Обмен заказами | Выключить |
| Каталог, характеристики, цены/остатки | Включить для исследования связей; доступность сочетания проверить в форме |
| Изображения | Выключить |
| Все данные / изменения | Все данные согласованного небольшого набора; возможность отбора ещё проверить |
| Без идентификатора сессии / без подтверждения импорта | Выключить |
| Регламентное задание | Выключить до ручной проверки |

Выбор вида цены «Розничная», единственного склада и вычета резервов должен быть подтверждён в **штатной** форме. Значения ранее осмотренного профиля Битрикс к ней не относятся. Если нужного поля нет, сначала выяснить фактическую семантику выгружаемых данных, не добавлять неизвестную настройку и не вычитать резерв второй раз.

## После согласованного запуска

1. Сопоставить текст результата в1С с журналом диагностического сеанса. Сохранённая часть ещё не доказывает полный файл или завершённую выгрузку.
2. Проверить порядок/имена/размеры/контрольные суммы частей, затем структуру фактически полученных XML. Рабочие данные не публиковать; в тесты переносить только обезличенные примеры.
3. Проверить ключи товаров/характеристик, вид цены, валюту/единицы, склад, резерв, ноль/отсутствие, признаки полного/частичного обмена. Сверить несколько реальных значений с1С без создания продаж/резервов ради теста.
4. Если отправитель остановился на первом `import` и цены/остатки не передал, рассмотреть отдельный согласованный проход в имеющемся режиме обновления цен/остатков. Получение нужных файлов этим режимом ещё не доказано. Не обходить остановку ложным `success`.
5. Последующий диагностический проход начинать новым сеансом, сохраняя прежние исходные байты. Одинаковые части не удалять как дубликаты: без номера/смещения их смысл неоднозначен.

Сохранять различие между получением байтов, успешным импортом файла и завершением всего обмена. Только после фактической проверки фиксируется контракт9А; сопоставление9Б, промышленный приёмник9В и применение к сайту9Г выполняются далее по порядку. Режим12часов и устаревание24часа пока не испытаны.

## Поправка после реальной выгрузки — 15 октября 2026

Владелец поручил продолжить пробную выгрузку и вручную сохранил отдельный штатный узел с фактическим именем «Выгрузка товаров», кодом 000000001. Предыдущая остановка на проверке соединения — история. В форме отбора прочитаны один выбранный товар, цена «Розничная», склад «Магазин»; владелец подтвердил заполнение условий. Автоматические действия в1С не выполнялись.

Выявлены две ошибки диагностики:

- HTTP429: четыре успешные авторизации исчерпали лимит запуска. Фактически один ручной обмен вызывает два checkauth. Восстановление выполнено перезапуском только приёмника через экспортированную функцию с прежними локальными реквизитами; обычный CLI-запуск генерирует новые. Лимит4 сохранён, старые каталоги захвата не удалены.
- HTTP400 на init/file: установленная1С добавляет параметр sessid одновременно с правильным cookie. Прежний whitelist query-параметров отклонял запрос до обработки. Дополнительные параметры теперь игнорируются; их значения не используются для авторизации и не записываются в метаданные. Дубли параметров, cookie-проверка, Host/Origin, методы, запретsale, пути/лимиты и отказimport сохранены.

После исправления фактически получен import0_1.xml, 3429байт, SHA256 37c8463ee9aa5f6ad08f25e1a8ce6dfa1f0c4bf23bba94eaa1a67b7241340d15.
