# Архитектура Grace Cosmetics

Состояние после этапа 0, 17 сентября 2026. Рабочая папка — `D:\grace`. Это существующее приложение из версии 7 Sites, а не новый starter. Происхождение — `TRANSFER.md`, перенос на D — `MOVE-TO-D.md`, выявленные ошибки — `ARCHITECTURE-AUDIT.md`.

## Стек и запуск

React 19.2.6, Vinext 1.0.0-beta.5, Vite 8.0.13, TypeScript 5.9.3; API и соглашения маршрутов Next 16.2.6. Версии установлены по существующему `package-lock.json`. Компоненты используют Tailwind 4, локальные `components/ui`, Radix и Lucide; меняется прикладная композиция, не vendored primitives.

`scripts/run-framework.mjs` выбирает режим по `.sites-runtime/execution-profile.json`; здесь `portable`. Разработка: Vinext на `127.0.0.1:5173`. Сборка создаёт Worker в `dist/server` и клиентские ресурсы в `dist/client`. `npm start` запускает собранный Worker локально через Wrangler, не публикует его. Конфигурация — `vite.config.ts`, `build/sites-vite-plugin.ts` и `.openai/hosting.json`.

Неизвестные товары, категории, бренды и подборки дают 404. Существующие URL сохранены. `components/site-link.tsx` сохраняет принятую в этом проекте навигацию.

## Источники данных и поток

1. `data/products.json` — 4 526 семейств товаров с 6 089 вариантами. `navigation.json` — 117 узлов шести пользовательских разделов; `taxonomy.json` — импортная классификация. `brands.json` — 350 брендов, `summary.json` — отчёт импорта.
2. Серверный `lib/catalog.ts` накладывает `product-images.json` на поле image, строит карту ID и нормализованный поисковый индекс. Поиск учитывает название, бренд, sourceSkus, подписи и SKU вариантов. Категория включает дочерние пути. Фильтры бренда и типа варианта, сортировки и страницы по 24 карточки живут здесь.
3. Серверные страницы вызывают запросы напрямую; клиент получает только нужные записи через props или API. В API нет произвольного ограничения числа ID избранного; Set обеспечивает проверку принадлежности без вложенного линейного поиска. Ответ остаётся пагинированным, с прежним `private, max-age=30`.
4. Изображения страниц и товаров — локальный `public/`. Три настоящие товарные фотографии заданы маппингом, у остальных карточек остаются явные заглушки. Нет загрузок в R2 или динамического внешнего CDN.

Основной XLSX лежит в `materials/`. **`scripts/import-catalog.py` читает таблицы, но перезаписывает JSON и отчёт импорта.** Он не вызывается сборкой или приложением. Второй оригинальный XLSX отсутствует; повторный импорт с заменой по догадке запрещён.

## Товары, варианты и цены

- Контракт `Product`/`Variant` — `lib/catalog-types.ts`. Product содержит семейство, paths и варианты; Variant имеет собственный уникальный id, sku или null, label, type, price, availability и необязательный format.
- ID — ключи ссылок, избранного и корзины. Нельзя переименовывать их, разрывать связи вариантов или незаметно менять значение старого ID.
- Текущие карточки каталога представляют семейства. `ProductDetail` первоначально выбирает первый вариант, затем отображает цену и код выбранного. Новые карточки конкретных вариантов — отдельный будущий этап, здесь не внедрялись.
- `pricing.ts`: только конечное положительное число считается известной ценой; отсутствие отображается `— ₽`. `productPrice` может показывать минимальную цену с «от» для семейства; `showcasePrice` дополнительно поясняет единственный оценённый вариант. В корзине используется цена конкретного сохранённого варианта, без подстановки минимальной цены семейства.
- Цены исторические: 5 029 положительных и 1 060 null. Все availability=`unknown`. Исторические остатки XLSX не превращаются в актуальное наличие. Скидки не вычисляются по выдуманным данным.

## Браузерное состояние

| Ключ localStorage | Формат и назначение |
|---|---|
| `grace-favorites` | `string[]` ID семейств; актуальные карточки загружаются API |
| `grace-bag` | `{product: Product, variant: Variant, quantity: number}[]`; снимки выбранных товаров и вариантов |
| `grace-searches` | Последние пять строк поиска |
| `grace-viewed` | Последние 12 ID, недавно просмотренный первым |

`lib/shop-state.ts` содержит независимое чтение/запись ключей, проверку данных и простые операции корзины. Доступ к localStorage выполняется только при вызове функций в браузере; тесты подставляют хранилище в памяти. Объекты из JSON проверяются как unknown, а не объявляются доверенными TypeScript-приведением.

Корректные старые снимки сохраняются без пересчёта цены. Вариант должен присутствовать в сохранённом семействе; количество — целое 1–99. Монтирование StoreShell не перезаписывает ключи: ссылка на прочитанное значение запоминается, сохранение происходит после изменения пользователем. Некорректные строки не попадают в интерфейс, исходная запись остаётся до изменения соответствующего списка. Ошибка сохранения корзины/избранного показывается уведомлением; текущий выбор остаётся в памяти вкладки. Ключи и JSON-формат не мигрировались, откат к прежнему коду не требует преобразования корректных данных.

Браузерные снимки **не являются доверенным серверным источником цен или заказом**. Текущая корзина помогает вручную передать список менеджеру в Instagram; кнопка копирования ничего не отправляет. Нет серверного аккаунта, оформления, синхронизации между устройствами или автоматической отправки. Данные телефона не переносились. Адрес localhost сохранён при переносе папки; сам путь на диске не меняет origin браузера.

## Конфигурация и границы безопасности

В текущем приложении нет обязательных секретов или runtime-переменных. `.openai/hosting.json` хранит прежний project_id; `d1` и `r2` равны null. `db/schema.ts` пуст, `db/index.ts`, `examples/d1` и `app/chatgpt-auth.ts` — неиспользуемые заготовки. Их наличие не означает подключённую БД или кабинет.

`CLOUDFLARE_CF_FETCH_ENABLED` и `WRANGLER_SEND_METRICS` по умолчанию false; Wrangler/Miniflare хранят локальное состояние в `.wrangler`. Portable-профиль умеет тестовый ChatGPT-вход только для loopback-разработки, он не используется магазином и не заменяет будущий доступ по телефону. `.sites-runtime`, `.wrangler`, `.env*`, сборка и зависимости игнорируются Git. Секреты нельзя помещать в public, props, клиентские переменные или отчёты.

## Где вносить будущие изменения

- Вёрстка/внешний вид: соответствующий компонент, `app/globals.css` или существующий CSS-модуль; тема, блоки и сценарии меняются в своих этапах.
- Поиск/категории/фильтры/пагинация: `catalog.ts` и `catalog-page.ts`. Правило отображения цены: `pricing.ts`, пояснения главной — `showcase-product.ts`.
- Источник каталога: серверная граница `catalog.ts`, существующие Product/Variant и их ID. Обмен 1С должен отдельно определить сопоставление и свежесть данных; не добавлять сетевой обмен в клиентские карточки.
- Заказы: новые серверные маршруты и постоянное хранилище в соответствующем этапе. Сервер заново проверяет вариант, цену, доступность и повтор запроса; браузерный снимок корзины не доверяется.
- Уведомления: серверная задача с повторной обработкой после сохранения заказа/подписки. Не отправлять сообщения из рендера карточки; не терять заказ при сбое сервиса.
- Кабинет: подтверждённая сессия/телефон и авторизация доступа к данным. Один введённый номер телефона не даёт права читать историю. Готовой реализации сейчас нет.

Это описание мест будущего подключения, а не реализация или выбор внешних сервисов.
