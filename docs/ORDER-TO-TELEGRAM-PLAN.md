# От формы заказа до рабочей Telegram-группы

**Последнее поручение владельца 11 октября 2026:** последовательно оформить через форму сайта два вымышленных заказа и получить уведомления в существующей группе **«Тест группа»**. Сначала небольшой заказ, затем более сложный примерно на 100 000 ₽ с парфюмерными распивами и другими товарами. В группе несколько участников. Это разрешение на финальную проверку; отдельное предварительное сообщение и повторное общее согласие не нужны. Адресат уже проверен по точному ID: одно название не определяет группу однозначно.

Шаги **1–4** приняты: 20 тестов Telegram, 53 регрессионных теста, TypeScript и одна сборка прошли; бот, точная группа и изолированная D1 проверены. Шаг **5** выполнен, владелец подтвердил первое уведомление. Шаг **6** также выполнен: второй заказ через форму на **99 435 ₽** сохранён, принят Telegram и подтверждён владельцем. В D1 теперь 4 заявки/4 задания, прежние 2 записи не изменены; повтор обоих новых заданий вернул `idle`. Итоговая сохранность 1 446 файлов подтверждена. [Квитанции и живые доказательства](STEP-10V-E2E.md). Полностью закрыто **13/30**, настоящие заявки не принимаются. Живой СДЭК остаётся отложенным и незавершённым. Полная инструкция — [Telegram: настройка и восстановление](TELEGRAM-NOTIFICATIONS.md).

## 1. Подготовить локальный обработчик

Состояние: **локально реализован и принят независимой проверкой**. Существующая заявка 10Б и задание очереди сохраняются вместе. Подготовлена отправка сохранённого снимка: номер заявки, вымышленные контакты, точные варианты/количества, сумма товаров, доставка и комментарий. Длинные заявки делятся на части без потери позиций; каждая принятая часть фиксируется. Только заданная группа/супергруппа, секреты на сервере, без публичной команды запуска.

Результат шага: локальная программа умеет обработать искусственную заявку через подставной Telegram-транспорт. В этом искусственном режиме запросов Telegram нет.

## 2. Проверить ошибки до живого подключения

Состояние: **принят независимой проверкой**. Проверены обычный успех, длинное сообщение, одновременный запуск, ошибку доступа, ограничение частоты, потерю ответа после возможного приёма, перезапуск процесса и ручную сверку. Подтверждённые части не повторяются; `delivery_unknown` не возвращается к автоматической отправке. Заявка сохраняется при любой ошибке канала.

Условие завершения шага: тесты и независимая проверка подтверждают поведение, сборка проходит, документация соответствует реализации. Искусственные задания этого шага не должны попасть в настоящую группу.

## 3. Создать бота и безопасно настроить группу

Состояние: **выполнено**. Бот создан, token сохранён, добавление в группу подтверждено владельцем и API. Повторно создавать бота, вводить token или повторять служебную команду не нужно. Справка по управлению ботом — [официальное руководство Telegram](https://core.telegram.org/bots/features#botfather).

Token сохранён в отдельный игнорируемый файл `.dev.vars.telegram` через разрешённое владельцем локальное чтение буфера обмена, без вывода значения. Проверенный ID группы добавлен командой подключения. Файл содержит только `GRACE_TELEGRAM_BOT_TOKEN` и `GRACE_TELEGRAM_CHAT_ID`. Исходный `.dev.vars` с другими интеграциями не читался и не менялся. Значения не публикуются в чате, команде, исходниках или отчёте.

Помощник ввода оставлен для будущей настройки нового файла: первый запуск остановила политика PowerShell, диалоговый — ошибка загрузки встроенного модуля. Явная загрузка модуля исправлена и проверена, но реальный показ окна ещё не подтверждён. Текущий token уже сохранён другим разрешённым способом. Точные команды и границы — в [инструкции](TELEGRAM-NOTIFICATIONS.md).

Название группы и сходное имя не заменяют проверенный ID. В этой настройке найден ровно один адресат; фактическое название **«Тест группа»** сверено с API. При будущей неоднозначности или необходимости темы нужен отдельный выбор, а не автоматическое переназначение.

## 4. Проверить доступ без предварительного сообщения

Состояние: **выполнено: настройки, права и соответствие изолированной базы проверены**. Владелец отправил точную служебную команду. Найден единственный адресат с фактическим названием **«Тест группа»** и типом `group`; `connect --live` успешно сохранил числовой ID в игнорируемый файл. Отдельный `preflight --live` вернул `ok: true`, подтвердив бота, точную группу, членство и право писать. Сам этап проверки доступа сообщений не отправлял; отправки выполнены позже в шагах 5–6.

Служебная команда `/grace_connect@grace_orders_test_bot` использована только для получения метаданных адресата; бот на неё не отвечал. Повторять её не нужно. Обычные сообщения и личные чаты для выбора группы игнорируются. Уже заданная группа не переназначается. Точные команды для обслуживания приведены в [инструкции](TELEGRAM-NOTIFICATIONS.md).

Независимый проверяющий подтвердил, что обработчик использует ту же изолированную базу, в которую пишет тестовая форма сайта. Обычный сайт остаётся закрыт для реальных заявок. Настоящий запуск ограничивается одним новым номером тестовой заявки и уже подтверждённой группой. Вся накопившаяся тестовая очередь не отправляется. Успешная проверка доступа не заменяет проверку формы, базы и обработчика.

## 5. Первый небольшой заказ: форма → база → Telegram

Состояние: **выполнено**. Форма сохранила `81c4b863-d689-4b70-8b15-4ea3ea0d39e8`, сумма **2 090 ₽**. В D1 `sent`, одна попытка, 1/1 часть; Telegram `message_id: 3`. Владелец подтвердил «да пришло». Повтор обработки вернул `idle`, нового сообщения нет. [Доказательства](STEP-10V-E2E.md).

В выполненном сценарии использована следующая вымышленная почтовая заявка; повторно её оформлять не нужно:

| Поле | Искусственное значение |
|---|---|
| ФИО | Анна Сергеевна Смирнова |
| Телефон | +7 000 000-00-00; не использовать для звонков или сообщений |
| Доставка | Почта России |
| Регион | Тестовая область |
| Город | Тестовый город |
| Индекс | 000000 |
| Адрес | Тестовая улица, дом 0 |
| Квартира | Оставить пустой |
| Комментарий | ТЕСТ. Вымышленные данные. Не обрабатывать. |
| Товар | Гидрофильное масло Anua 200 мл, вариант gc002705, артикул GC002705; каталожная цена 2090 ₽ |
| Количество | 1 шт. |

Цена и номер заявки заранее не выдумываются: цена берётся из проверяемых локальных данных, номер выдаёт сервер после сохранения. При изменении состава/цены пройти штатное подтверждение формы. Контакт с вымышленным покупателем не производится.

Последовательно проверено:

1. Форма показала номер только после сохранения; в изолированной базе есть ровно одна соответствующая заявка и одно задание очереди.
2. Серверный обработчик отправил уведомление именно этой заявки в проверенную группу **«Тест группа»**. Сохранены ID принятого сообщения и состояние очереди.
3. Уведомление фактически видно в нужной группе, с тем же номером, товаром, количеством, суммой, вымышленными контактами и отметкой ТЕСТ.
4. Повтор обработки завершённого задания не посылает ещё одно уведомление. Прочтение участниками группы отдельно не утверждается.

Финальный результат — совпадающая цепочка формы, сохранённой заявки и видимого уведомления без дубля в этом проверенном сценарии. При потере ответа сначала ручная сверка по [инструкции восстановления](TELEGRAM-NOTIFICATIONS.md), без слепого повторения. Если увидеть группу невозможно, зафиксировать только подтверждение API и оставить визуальное получение неподтверждённым.

Постоянный хостинг, рабочее хранилище, расписание, актуальная 1С и живой СДЭК остаются отдельными зависимостями. Эта проверка не публикует сайт и не открывает настоящие заказы.

## 6. Второй заказ примерно на 100 000 ₽ — последняя проверка

Состояние: **выполнено: форма, база, приём Telegram и видимость владельцем подтверждены**. Заказ `c26626ff-39c3-4f20-89d2-066c72e94b7d`: 13 вариантов по одной штуке, включая три распива по 1 мл, **99 435 ₽**. В D1 `sent`, одна попытка, 1/1 часть; Telegram `message_id: 4`. Владелец подтвердил «да пришла смс». Повтор вернул `idle`, предыдущие задания не изменены. [Состав, квитанция и доказательства](STEP-10V-E2E.md). Живое сообщение уместилось в одну часть, поэтому реальная многочастная отправка не утверждается.

После первого небольшого сценария в браузере собрана отдельная корзина в заданном диапазоне 95 000–105 000 ₽: парфюмерные распивы с точными объёмами и другие товары. Использованы существующие варианты и цены каталога, по одной штуке; тестовый остаток остался отдельным источником. Состав и сумма проверены до отправки формы. ФИО, резервный телефон, тестовый почтовый адрес и комментарий сохранены из шага 5.

Для второго заказа сохранены отдельные номер, снимок квитанции, строка заявки, текст уведомления и доказательство приёма. Обработан только его UUID; прежние задания и первый заказ не отправлены снова. Оба завершённых заказа повторно оформлять или отправлять не нужно. Владелец отдельно подтвердил фактическое наличие обоих уведомлений; API-ответ эту проверку не заменяет.
