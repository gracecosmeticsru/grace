# 10Б — изолированная подготовка серверного сохранения

11 октября 2026. Работа только в D:/grace. Полностью завершено **13/30**: 10А остаётся открытым из-за отложенного живого СДЭК; 10Б подготовлен локально, окончательное закрытие зависит от постоянного production-хранилища, актуальных цен/остатков после 9Г и уведомлений менеджеру. Реальные заявки закрыты, публикации не было.

## Реализация

- `POST /api/orders/session` создаёт гостевую HttpOnly/SameSite-сессию до отправки. В БД хранится хеш случайного токена; на HTTPS используется host-only Secure cookie. Нет публичного чтения заказа по номеру телефона или ID.
- `POST /api/orders` повторно проверяет неизвестный JSON, поля, точную принадлежность варианта товару, цену и доступное количество из серверного источника. Деньги — целые копейки; неизвестные значения закрывают приём. Клиентская цена служит только ожиданием для сравнения. Изменения требуют отдельного подтверждения.
- D1 хранит неизменяемый снимок заявки. SQL-триггер атомарно создаёт задание Telegram в `order_outbox`; отправителя пока нет. Ошибка создания задания откатывает заявку. Повтор сохраняет один заказ/одно задание даже после потери ответа и перезапуска.
- Ключ попытки уникален глобально; получить результат повтора может только прежняя гостевая сессия. Потеря/истечение cookie с прежним ключом возвращает конфликт без чужого номера заказа и без дубля.
- Форма сохраняет поля/корзину при ошибке. В sessionStorage попадают только случайный ключ и солёный хеш запроса; контакты туда не записываются. После перезагрузки для безопасного повтора требуется ввести точно прежние данные. После достоверного успеха вычитаются только отправленные количества, другие позиции и добавления сохраняются.
- Включение доступно лишь в явно заданном локальном тестовом runtime и на loopback. Каталожные цены и остаток 1 помечены `isolated-test`; это не актуальные данные 1С. Обычный сайт и production-сборка сохраняют закрытый приём.

## Независимая проверка

Агенты разделили сервер, клиент и интеграцию. Выполнены четыре прохода проверки каждой части. Интеграционная проверка обнаружила риск дубля после потери гостевой cookie; исправление глобальной уникальности ключа и удержания неподтверждённого запроса проверено повторно.

- Независимо повторно выполнены Unlazy-проверки серверного листа (15 тестов на настоящем локальном Miniflare/D1) и клиентского листа (24 теста, включая существующую корзину/форму).
- Итоговые runnable-критерии корневого плана G1/G2/G3/G4/G7 прошли с привязанным автоматическим evidence: серверные и общие регрессии, TypeScript и production build, **1446 защищённых файлов без изменений**, обычные `/api/orders/session` и `/api/orders` возвращают **503 без Set-Cookie**. Логи типов/сборки и `preservation.json` сохранены в `artifacts/step-10b/`. Сборка содержит лишь предупреждение о времени плагинов; ошибок нет.
- Серверные тесты покрывают подмену типов/суммы/варианта, CSRF, предел тела и таймаут незаконченного потока, лимиты запросов, нулевое/неизвестное наличие, параллельные повторы, иной payload с тем же ключом, потерю/истечение cookie, полный перезапуск D1, откат при ошибке outbox, потерю ответа после реальной записи и закрытый непроверенный ПВЗ.
- Браузерная проверка через CUA, отдельный origin `127.0.0.1:5178`, только вымышленные контакты. Товар добавлен обычной кнопкой. Пустая форма показывает ошибки и фокусирует имя. Отключённый сервер сохраняет поля/корзину и предлагает повтор.
- В тестовой D1 временно создан отказ вставки outbox: форма показала ошибку, поля остались заполненными и заблокированными от изменения неподтверждённой попытки; БД содержала **0 заявок / 0 заданий**. После удаления отказа тот же повтор дал **1/1**, экран сохранения получил фокус, отправленный товар убран из корзины.
- Для проверки изменения цены временный изолированный серверный источник вернул 2801 ₽ вместо каталожных 2800 ₽. До подтверждения новой заявки нет; отказ сохранил поля/корзину; отдельное подтверждение дало **2 заявки / 2 задания**. Временная поправка цены удалена, исходный runtime восстановлен побайтно. Каталог не менялся.
- На ширинах **320, 390 и 1440 CSSpx** документ не переполнялся: clientWidth/scrollWidth соответственно **305/305, 375/375, 1425/1425**. Разница 15 px — полоса прокрутки. Мобильные кнопки подтверждения перенесены в пределах карточки и доступны при прокрутке. Просмотрены отдельные снимки viewport, override сброшен.
- Артефакты: `artifacts/step-10b/checkout-desktop.png`, `network-retry.png`, `storage-failure.png`, `saved-receipt.png`, `quote-320-actions.png`, `quote-390-actions.png`, `checkout-1440.png`, `quote-confirmed.png`. Полные мобильные склейки не используются как доказательство.

Изолированный сервер остановлен. Основной `127.0.0.1:5173` оставлен работающим; тесты не выполняли действий изменения его корзины.
