# WhatsApp для заявок Grace — исследование 10А

**Историческое исследование, канал менеджеру изменён владельцем.** Действующее решение — [Telegram первым в10В](MANAGER-NOTIFICATIONS.md), Gmail позже при необходимости. Этот документ не предписывает подключать платного WhatsApp-посредника. WhatsApp сохраняется для общения менеджера с покупателем и ранее утверждённых подписок этапа11.

Рабочий контакт уже предоставлен владельцем и хранится в `lib/store-details.ts` / `docs/step05v-owner-data.md`. Повторно его не запрашивали. В текущем разговоре владелец дважды подтвердил: WhatsApp используется **только в приложении на телефоне**. API/BSP не подключён или не подтверждён; готовность автоматической отправки отсутствует. Не требуется сейчас различать обычное приложение и Business App — форму это не блокирует.

Официальный путь для исследования и выбора в 10В — WhatsApp Business Platform Cloud API напрямую либо через официального провайдера. [Документация Meta в Postman](https://www.postman.com/meta/whatsapp-business-platform/collection/wlk6lh4/whatsapp-cloud-api) описывает business portfolio, WABA, бизнес-номер отправителя и access token; отправка выполняется сервером через `/{Phone-Number-ID}/messages`. Обычная ссылка `wa.me` и приложение на телефоне не создают такого серверного подключения.

По [политике WhatsApp Business](https://business.whatsapp.com/policy) для инициированного бизнесом разговора требуется утверждённый шаблон и согласие получателя; свободный ответ доступен в 24-часовом окне после сообщения адресата. Действующая открытая политика датирована 23 сентября 2026. Нельзя строить круглосуточное уведомление менеджера на предположении, что это окно всегда открыто. Получение HTTP-ответа API не доказывает доставку: понадобится проверка статусов.

Вывод для Grace: канал технически существует, но его пригодность для уведомления конкретного менеджера и доступность для конкретного аккаунта ещё не подтверждены. Категорию/допуск шаблона, работу с действующим номером и необходимые изменения не считать согласованными заранее. Другой канал без решения владельца не подставлять.

## Что остаётся на 10В

1. Выбрать поддерживаемого провайдера или прямую Cloud API и проверить доступность для аккаунта Grace и сценария уведомления менеджера.
2. Согласовать номер отправителя и номер получателя: опубликованный контакт сам по себе не является API-отправителем. Сохранить работу телефонного приложения; условия переноса/совместного использования выяснять у выбранного сервиса, не мигрировать номер автоматически.
3. Получить серверные доступы, WABA/Phone Number ID и необходимые разрешения безопасным способом. Секреты не размещать в клиенте, репозитории, отчётах или чате.
4. Подготовить и согласовать шаблон; подтвердить получение уведомлений менеджером. После постоянного сохранения заявки — очередь отправки, повтор без дублей, обработка отказов и статусов доставки. Не сообщать покупателю «передано менеджеру», пока это не подтверждено.
5. Перед настоящим тестовым сообщением отдельно согласовать адресата и разрешение владельца; использовать обезличенные тестовые данные. В 10А сообщений не отправляли.

Прямые страницы developers.facebook.com вернули 429/ошибку загрузки. Использована официальная коллекция **Meta** в Postman и открытая политика WhatsApp; ограничения чтения не выданы за проверку настроенного аккаунта. Выбор провайдера, регистрация, тарифы конкретного аккаунта и реальная доставка пока не проверены.
