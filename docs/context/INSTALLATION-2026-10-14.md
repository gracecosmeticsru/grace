## Слабости исходного плана и принятые решения

1. `.codex/` игнорируется и запрещён к публикации действующими правилами. Контекст там исчезнет при восстановлении из GitHub. Канонический путь адаптирован к отслеживаемому docs/context, без изменения .gitignore/hooks.
2. Запрет commit/push в ТЗ противоречит поручению 13.10. Владелец явно делегировал решение после объяснения конфликта; применён обычный commit/push по правилам проекта. Новые коммиты не переписывают историю и не публикуют сайт.
3. Markdown сам не обеспечивает сохранность/контроль DONE. Добавлены реальные helpers и отрицательные тесты. PASS/waiver остаются проверяемым агентом свидетельством, не доказательством истинности произвольного ввода.
4. При прерывании записи checkpoint новее task: восстановление берёт валидный snapshot только если task совпадает с наблюдённым предшественником. Ручные изменения не затираются. Обычное восстановление DONE/CANCELLED не выдумывает повторное открытие.
5. Старые инструкции одновременно содержат «D1 не подключена» и более новый hosted-приём. Утверждения разделены по датам/источникам; исторические отчёты сохранены. Сегодня живые сервисы не проверены.

## Продолжение и ограничения

Для новой задачи достаточно написать: «Начни новую задачу: …». Для незавершённой: «Продолжи TASK-…: сверь последнюю подтверждённую точку с Git и файлами». Агент использует [протокол](README.md); task + последний валидный checkpoint — handoff, дополнительного глобального handoff нет. После штатного commit отличие HEAD от checkpoint ожидаемо, но требует сверки конкретного commit и хешей, не автоматического игнорирования.

NOT RUN: сборка приложения, TypeScript приложения, браузер/физические телефоны, живые D1/Telegram/СДЭК и деплой — функциональный код не менялся, эти проверки не требуются для Context OS. Не выполнялись новые заказы, уведомления, миграции или установки пакетов. Прежний локальный сервер не останавливался.

Не обещаны: гарантированная блокировка процессов, атомарность нескольких файлов, fsync/защита от любого аппаратного сбоя, истинность поддельных PASS/цитат, автоматическое сохранение каждого сообщения, численная экономия токенов. Несохранённое после последнего checkpoint нужно восстановить из worktree. GitHub сохраняет только отправленные версии; новые секреты/данные покупателей запрещены и в context docs.

Локальные производные backup/cache Graphify остаются вне коммита. Автоматическая проверка отклонила команду их очистки с причиной `blocked by policy`; повторных попыток обхода не было. Это не изменения приложения и не помеха сохранению контекста.
